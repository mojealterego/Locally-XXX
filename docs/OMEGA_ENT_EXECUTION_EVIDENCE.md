## Implementacja
- Repozytorium PostgreSQL: transakcje na jednym pool client, SET LOCAL ROLE omega_runtime, sprawdzenie roli bez superuser/BYPASSRLS, set_config tenant parametryzowane, jawne WHERE tenant_id, SQL statement timeout, rollback/release. RAG model-specific cosine query, 768 float values, kontrola danych, immutable insert on conflict. Publiczny RAG API i grant per dokument pozostają OPEN; bez arbitralnego SQL. 
- Migration 002: izolowana tabela review_tasks, FORCE RLS, ograniczone uprawnienia kolumn, terminalny status z reviewer różnym od submitter, trigger dopuszczalnych przejść. Montowana przy inicjalizacji świeżej bazy; istniejąca baza wymaga migracji operatora. DDL nie wykonana na realnym PostgreSQL.
- BullMQ: FlowProducer parent-child, referencje tenant/id, deterministic SHA-256 job IDs, 3 próby, exponential backoff, failParentOnFailure. Worker re-check PDP, walidacja manifestu i agregacja dwóch wyników po digest. Concurrency 4/2. Metadata/tools checks są strukturalne — obie sprawdzają kontrakt całego draftu, nie rzeczywiste wykonanie narzędzi. Brak poświadczeń w payload. Re-use flow zweryfikowany w adapterze testowym; wyścigi add, retencja, globalny limit per tenant, prawdziwy crash recovery OPEN.
- Temporal: SDK bindings i worker, stable workflow ID/REJECT_DUPLICATE, retry budget, kontrolowane oczekiwanie 120 * 5 s plus activity time, execution timeout 30 min. Review API odrębny loopback 3001, HTTP 202 po potwierdzeniu startu, OIDC i Permit. Decyzja approve/reject w DB CAS dla konkretnego digest, inny reviewer; workflow odczytuje stan w trwałej activity. Signal, outbox/reconciliation i recovery zamkniętego failed workflow OPEN. Przy błędzie workflow lub cofnięciu uprawnień zadanie może pozostać PENDING/REVIEWED do interwencji. Nie publikuje agenta, nie robi LLM inference, nie uruchamia kodu ani Firecracker. APPROVED oznacza wyłącznie przegląd strukturalny.
- TLS konfiguracja klientów DB/Redis/Temporal, sekrety z plików. Istniejący bootstrap Compose nie konfiguruje pełnego TLS ani klastra Keycloak/Temporal; środowisko usług musi być przygotowane osobno.
- RLS GUC chroni przed pomyłką z parametrami, nie przed przejęciem zaufanego runtime DB login umożliwiającego ustawienie dowolnego tenant. Worker działa jako zaufana usługa, nie wykonuje arbitralnego kodu. Revocation/TOCTOU między decyzją PDP i operacją oraz dokładna polityka narzędzi są nadal wymaganiami integracyjnymi.
